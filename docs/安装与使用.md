# 园圃工作台 — Omni Toolbox 版 1.0.2





## 1.0.2 更新（2026-11-06）

作者：**Sanse**。

园圃界面新增「分类方式」：

- **按房区**：保留原来的房区筛选方式，可选择全部房区或指定住宅区。
- **按房屋**：选择「全部房屋」时按每栋房屋分组显示园圃；也可通过房屋下拉框只查看某一栋。房屋地址显示服务器、房区、区号及门牌。同一栋房屋内的多块园圃归为同组，相同房区或相同显示名称不会把不同房屋合并。

分类方式会保存在配置中，旧配置默认继续使用「按房区」。两种方式各自保留当前界面内的筛选选择；切换后会让当前园圃跟随可见范围。工作台的园圃列表也跟随同一筛选。

总览卡片高度同时计入房屋标题和操作按钮。1.0.1 的未绑定园圃保留、删除确认、四个快捷候选及八格中央文字居中继续保留。

停用旧模块后替换 DLL 并重新加载，保留原配置。此更新只改变分类和显示，不会迁移园圃身份、布局或种植记录。

本次通过源码/合并源码编译、分类与配置保存检查，并用原生 ImGui 验证两个宽度下的分类切换、房屋下拉、房区下拉、全部房屋及选择单栋房屋。未将新版加载到游戏执行园艺操作。

## 作物名称自动回填

这次已在你的聊天记录中确认，游戏会输出“风茄正茁壮成长。”“库尔札斯茶叶正茁壮成长。”等消息；它们的来源为 SystemMessage / None，而护理成功消息的来源为 LocalPlayer。旧版仅处理后者，因此漏掉了名称。

新版同时处理这类明确名称消息，使用游戏 GardeningSeed / Item 表查找对应种子，并核对房屋、目标对象、园圃组及游戏菜单的地垄号后补录。自动操作会在点击菜单前处理待识别消息，避免菜单关闭太快而漏录；手动点开格位也支持识别。

更新后关闭并重新点开相应格位，或执行一次护理，聊天再次出现具体作物名后，“时间记录”的种子名称会自动补齐。已有护理、施肥及种植时间保持原值；未知的种植时间仍为“未记录”，不会因识别名称而重新计时。种子栏悬停可查看作物名称及识别时间。

如果同一作物对应多个种子，显示已识别的作物名并标记种子待确认，不猜测。识别日志单独标注为“作物识别”。新一轮种植会清除上一轮识别信息。旧聊天没有可验证的格位身份，不按旧消息顺序倒推或批量绑定。

本次通过聊天与菜单只读观察核对了消息格式；新版本的自动回填仍需更新后在游戏内确认。

## 安装

1. 把压缩包完整解压到固定目录，保留 `KotiyaGarden.dll`、`KotiyaGarden.deps.json`、`KotiyaGarden.pdb`。
2. 打开 Omni Toolbox，在本地模块的添加入口登记 `KotiyaGarden.dll` 的绝对路径。不要覆盖 Omni Toolbox 本体或 Common DLL。
3. 在「树树妙妙屋 → 本地」查找「园圃工作台」，确认作者 Sanse 后开启。
4. 在模块设置中打开工作台，靠近有权限的园圃，点击「刷新附近园圃」。也可用模块命令 `/omni KotiyaGarden open` 打开独立窗口；准确命令以 Omni 为模块显示的命令项为准。
5. 使用 Omni 版时，先停用 DR 中的「园圃布局作业」及原版「自动园圃作业」，避免同时运行两套园艺任务。DR 里的其他功能可以继续使用。

只登记其中一个入口：推荐 DLL。对应源码包根目录的 `KotiyaGarden.cs` 是完整合并源码，可供支持源码编译的本地模块入口使用；不要把 DLL 与源码同时登记。

本仓库同时提供在线安装：在 Omni 的「插件设置 → 在线模块」添加 https://github.com/KKsanse/OmniToolbox.sanse ，刷新安装后在「树树妙妙屋 → 在线」启用。在线版与本地版只启用一个。手动安装包不会自动安装或启用模块；不要替换 Omni 自身程序集。

## 与“自动跳过对话”的关系

已只读查看你游戏里的 Omni 设置页：“自动跳过对话”当前已开启，说明为自动点击普通 Talk 对话窗口，不直接绕过游戏事件流程。

- 按其说明，它可以配合园圃护理时的普通对话推进，不负责土壤、种子、肥料选择或播种的是非确认。
- 本模块另有「园圃护理时自动推进对话」，默认开启。只在本模块正在护理、当前房屋与目标格位仍匹配时点击该步骤的普通 Talk，并限制每格一次。
- 想沿用 Omni 的对话推进，可以关闭本模块这一项进行对照。想让园圃模块独立处理，则保持本模块这一项开启。这个设置位于本模块「提醒设置」页。
- 土种选择、播种确认与成功核对由本模块流程负责，不把任意确认交给对话跳过功能。

本次检查确认了设置说明及开关，没有执行护理动作；Omni 跳过对话与新模块的实际配合仍需加载后验证。没有改动你的 Omni 对话开关。

## 保留的园圃功能

- 四格圆形园圃、六格方形园圃、八格高级园圃的家具扫描、格位核对、布局编辑、材料预览、种植与维护。
- 每格选择种子，统一或单格土壤，复制 / 粘贴种子，复用已选种子，调整播种顺序，游戏目标校准。
- 每块园圃独立绑定布局；按住宅区筛选，显示服务器、区号、门牌，重命名园圃。
- 紧凑总览、园圃工作台、种植 / 护理 / 施肥记录、手动补记、执行记录。
- 操作前读取菜单，跳过空地、已成熟及不可用操作；游戏拒绝继续施肥时跳过，不伪造成功时间。
- 每块园圃内全部已记录的生长中作物到施肥提醒时间后合并提醒，护理提醒独立配置。
- `GLW1:` 预设分享码，与 DR 0.2.2 保持兼容。四格、六格和八格均可分享。

新建布局默认使用当前园圃格数。已有八格布局不会自动裁成四格或六格，请新建对应格数布局并绑定。示意图不保证游戏方位，需要时使用当前园圃的目标校准。

## 从 DR 版转移布局

两版使用独立配置，不会自动读取或覆盖 DR 的配置。

在 DR 版生成布局分享码，复制到 Omni 版的「预设分享 / 导入」，校验并导入。导入后到对应园圃附近刷新、核对格位，再绑定。

分享码只带布局、种子、土壤、映射和顺序，不包含房屋绑定、园圃名称或历史时间。需要的历史时间可按实际情况手动补记。原有 DR 配置保留。

## 数据与提醒

成功操作后会独立保存记录，不要求一直开着设置页。数据文件位于 Omni 插件配置目录下：

`TreeHouseLocalData/KotiyaGarden/state.json`

上一次保存保留为 `state.json.bak`。配置读取失败时停止启用并保留原文件。宿主也会管理模块的 Settings；本模块状态文件用于保存布局与持续更新的操作记录。

施肥提醒按每块园圃的最后一株到期时间合并，各园圃独立，不等待其他房屋。空地、已检测成熟及已收获格位不计入；生长中作物时间未知时需先补记。提醒每约 10 秒检查本地记录，列表手动刷新，未持续扫描所有园圃。

检测状态来自最近一次操作时的菜单，离开房屋后显示已保存信息。模块成功播种能记录准确种子；聊天出现明确作物名时也会自动补录，尚未取得名称时显示「种子未知」。外部插件、其他玩家的收获或重种，不保证能自动归属到格位，需要手动更新记录。
